# RTL Support

OUI has partial right-to-left support. Text and many layouts inherit the document direction, but some keyboard interactions and directional styling still assume left-to-right. Setting `dir="rtl"` does not make every component fully RTL-aware.

## App Setup

Set direction at the document or page boundary:

```html
<html lang="ar" dir="rtl">
    ...
</html>
```

Set both language and direction for the page. Language identifies the content for assistive technology; it does not set its direction automatically. For a right-to-left region within a left-to-right page:

```vue
<section lang="ar" dir="rtl">
    <Banner title="تم الحفظ" type="success">
        تم تحديث الإعدادات بنجاح.
    </Banner>
</section>
```

Document-level direction is the most reliable setup for overlays. Content teleported outside a regional `dir="rtl"` container inherits direction from its actual DOM ancestors, so check popups as well as their triggers. A regional direction setting alone does not reach every overlay.

## Consumer content

- Use logical utilities such as `ms-*`, `me-*`, `start-*`, `end-*`, `text-start`, and `text-end` in slots and surrounding layouts. Physical `left` / `right` utilities remain fixed.
- Translate visible copy and accessible labels. Direction does not translate built-in English labels; use supported attributes, props and slots where available.
- Isolate mixed-direction values such as account names and identifiers with `bdi`. Set `dir="ltr"` on fields that intentionally display left-to-right values, such as an email address, while keeping their surrounding labels in the page direction.

```vue
<p>المستخدم: <bdi>{{ accountName }}</bdi></p>
<Input dir="ltr" label="البريد الإلكتروني" type="email" />
```

## Current limitations

- **Tabs and nested dropdown menus:** horizontal arrow-key handling currently uses left-to-right rules.
- **Breadcrumb and Pagination:** directional chevrons do not automatically mirror.
- **ButtonGroup:** horizontal joined corners and border overlap use physical left/right styling.
- **Regional overlays:** popup direction can differ from the trigger when content is teleported outside the region.

The <a href="./?path=/docs/patterns-rtl-layouts--docs" target="_top">RTL Layouts pattern</a> shows a composed Arabic interface. It demonstrates inherited layout direction; it is not comprehensive RTL keyboard or localisation coverage. Check these limitations before choosing the affected components for an RTL application.

See the HTML guidance for [direction](https://developer.mozilla.org/en-US/docs/Web/HTML/Global_attributes/dir) and [mixed-direction text isolation](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/bdi).
